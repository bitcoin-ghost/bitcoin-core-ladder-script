Verify the Download

Each release ships a SHA256SUMS file plus a detached PGP signature SHA256SUMS.asc. Verify the signature first, then check the binary against the SHA file.

# 1. Import the release-signing key (one-time setup). gpg --keyserver keys.openpgp.org --recv-keys 777FE81F8CC077FD3D08055E852C2B3190F5B928 # 2. Verify SHA256SUMS was signed by the release key. gpg --verify SHA256SUMS.asc SHA256SUMS gpg: Good signature from "defenwycke <defenwycke@icloud.com>" # 3. Verify the binary archive matches. sha256sum -c SHA256SUMS --ignore-missing bitcoin-core-ladder-v30.0-ladder-0.1-x86_64-linux-gnu.tar.gz: OK
Release-signing key fingerprint: 777FE81F8CC077FD3D08055E852C2B3190F5B928 — this page is the canonical publication. If gpg --verify reports any other key, do not trust the binary. Cross-check against the same fingerprint in the repo's README.md.
Build from Source

If you would rather build it yourself (any platform, full test suite):

git clone https://github.com/defenwycke/bitcoin-core-ladder-script.git cd bitcoin-core-ladder-script cmake -B build -DCMAKE_BUILD_TYPE=Release cmake --build build -j2 # -j2 keeps WSL2 happy; on a real box use -j$(nproc)

liboqs is a hard build dependency for the post-quantum signature schemes — install via your package manager or build from github.com/open-quantum-safe/liboqs.

Quick Start

Configure (drop the snippet from the next section into ~/.bitcoin/bitcoin.conf and pick an rpcpassword):

mkdir -p ~/.bitcoin # Then paste the Signet Configuration block below into ~/.bitcoin/bitcoin.conf

Start the node:

./build/bin/bitcoind -daemon Bitcoin Core starting # wait for sync (~30 seconds on the Ladder Script signet) ./build/bin/bitcoin-cli -signet getblockcount 1216

Create a wallet:

./build/bin/bitcoin-cli -signet createwallet test ./build/bin/bitcoin-cli -signet -rpcwallet=test getnewaddress tb1q...

Create a Ladder Script transaction:

# parse a descriptor ./build/bin/bitcoin-cli -signet parseladder "ladder(sig(@alice))" \ '{"alice":"0279be667ef9dcbbac55a06295ce870b07029bfcdb2dce28d959f2815b16f81798"}' { "conditions_hex": "01010001010101000000", "mlsc_root": "443a7849...", "n_rungs": 1 } # format it back ./build/bin/bitcoin-cli -signet formatladder "01010001010101000000" { "descriptor": "ladder(sig(@?))" }
Signet Configuration
# Ladder Script Signet signet=1 [signet] server=1 txindex=1 fallbackfee=0.0001 # Ladder Script signet challenge signetchallenge=21036bae004d5cd7bb65742cdbf735bf6f3a384d69f4d52dba84689a3db972848f68ac # Seed node (Amsterdam) addnode=85.9.213.194 # Your RPC credentials rpcuser=ladder rpcpassword=changeme
Building

The repository is a Bitcoin Core v30.0 fork on the ladder-script branch — clone, install liboqs, and build with CMake:

git clone https://github.com/defenwycke/bitcoin-core-ladder-script.git cd bitcoin-core-ladder-script # liboqs is a HARD dependency — PQ schemes are part of the consensus surface, # so a node built without liboqs would silently disagree with PQ-enabled nodes. # On Debian/Ubuntu: build from source per https://github.com/open-quantum-safe/liboqs cmake -B build -DCMAKE_BUILD_TYPE=Release cmake --build build -j$(nproc) # Optional: -DENABLE_QABIO=OFF for the base block set without the QABIO extension
Forked from upstream Bitcoin Core v30.0. The 805-line patch lives across 29 files in src/; the 19,345-line library in 39 new files under src/rung/. A single boundary header (src/rung_shims.h) is the only place Core types meet library types. See Annotated Patch for the per-file walkthrough.
