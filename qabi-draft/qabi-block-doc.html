QABI

Quantum Atomic Batch Input. A PQ-only signature anchor that enables multiple independent UTXOs to be spent under a single post-quantum signature. Rejects classical schemes (Schnorr, ECDSA) at the evaluator level.

Signature Non-Invertible
Overview

QABI is the anchor block for QABIO (Quantum Atomic Batch Input/Output) — a protocol that achieves O(1) quantum signature overhead for N-party transactions through systematic aggregation rather than cryptographic construction.

A coordinator places QABI in one input of a RUNG_TX. The FALCON (or other PQ) signature covers SIGHASH_ALL, binding every input and output. Other inputs set their own spending conditions (OUTPUT_CHECK, INPUT_COUNT, SIG, etc.) to enforce trustless consent. If any party's conditions aren't met, the transaction fails atomically.

QABI is functionally identical to SIG with a PQ scheme, but rejects classical schemes at consensus level. This structural guarantee means a QABI-anchored transaction is always quantum resistant — it cannot accidentally fall back to Schnorr.

SCHEME
1 byte
PQ signature scheme: 0x10 (FALCON512), 0x11 (FALCON1024), 0x12 (DILITHIUM3), 0x13 (SPHINCS_SHA). Classical schemes (0x01 Schnorr, 0x02 ECDSA) are rejected.

PQ public key. 897 bytes (FALCON512), 1793 bytes (FALCON1024), 1952 bytes (DILITHIUM3), 32+ bytes (SPHINCS+). Folded into Merkle leaf via merkle_pub_key.
Witness
SIGNATURE
Variable
PQ signature over SIGHASH_ALL. ~666 bytes (FALCON512), ~3293 bytes (DILITHIUM3), ~49216 bytes (SPHINCS+).
Evaluation
  1. Extract SCHEME from conditions fields.
  2. Check IsPQScheme(scheme) — return UNSATISFIED if classical (Schnorr or ECDSA).
  3. Extract PUBKEY and SIGNATURE from witness fields.
  4. Verify PQ signature against PUBKEY using the specified scheme via EvalPQSig().
  5. Return SATISFIED on valid PQ signature.
Use Cases
  • Quantum-safe coinjoin — 100 participants, 1 FALCON signature. Privacy tools become economically viable at scale in a post-quantum world.
  • Exchange batch withdrawals — Thousands of withdrawals batched under one PQ anchor. One signature regardless of batch size.
  • Payment channel factories — Multiple Lightning channels opened in one transaction, all quantum secured.
  • Multi-party treasury — Independent parties bond their UTXOs under a single quantum seal with programmable governance via Ladder Script conditions.
  • PQ chain of custody — Outputs created by QABI are quantum secured from confirmation. Spending conditions can enforce another QABI for permanent quantum-only custody.
Descriptor Syntax
qabi(@alias)                    // default: FALCON512
qabi(@alias, falcon512)         // explicit FALCON-512
qabi(@alias, falcon1024)        // FALCON-1024
qabi(@alias, dilithium3)        // Dilithium3
qabi(@alias, sphincs_sha)       // SPHINCS+-SHA2-256f

Classical scheme names (schnorr, ecdsa) are rejected at parse time.
